# Deployment, security and recovery

Python 3.12 is the supported container/runtime target. Use `backend/requirements.txt` and the frontend lockfile. PostgreSQL is the Docker database; SQLite supports a single-machine local demo. Run the initial versioned migration before serving traffic. Do not run synthetic seeding with real audit data.

Production provisioning: set DEMO_MODE=false and a strong persistent SECRET_KEY, run the user-provisioning CLI, assign auditor/reviewer independently and use a TLS reverse proxy. Containers bind the frontend to localhost port 8080 by default; backend and database have no published ports. Terminate TLS before exposing the service remotely, enforce trusted origins and configure security headers appropriate to your reverse proxy. Store DB passwords, JWT secrets and optional provider keys in a secret manager.

JWTs expire in eight hours; server-side session revocation implements logout. Passwords are hashed with Werkzeug scrypt. Registration creates auditors only. Per-resource authorization covers retrieval/download/report APIs. Document originals are stored outside public assets under generated names. Unsafe archive paths, unsupported types, excessive expanded sizes and encrypted ZIPs are rejected. Parsing failures are visible. Configure MALWARE_SCANNER with an absolute executable path accepting one file argument and exit 0 for clean; nonzero/timeout rejects uploads. Without it, scanning is explicitly Not configured.

The demonstration limiter is process-local and keyed by direct client IP, not arbitrary forwarded headers. Production should use a shared Redis-backed limiter, reliable identity-level quotas, a durable job queue, request/worker timeouts, artifact retention policies and malware infrastructure. Concurrency locking/large-batch resource isolation need further deployment hardening. Never represent the demo as a production-certified financial system.

Backup PostgreSQL with pg_dump and preserve the evidence volume in the same backup epoch. Example: `docker compose exec -T db pg_dump -U auditflow auditflow > auditflow-backup.sql`. Back up encrypted to access-controlled storage; test a restore into an isolated instance. Restore the database and matching evidence volume together, verify stored file SHA-256 values, reindex active documents and inspect report/source references before reopening access. Vector values live in SQL and FAISS is rebuilt from authorized active chunks, so no separate vector artifact is required for recovery.

Optional LLM requests transmit only retrieved snippets to Anthropic when both ANTHROPIC_API_KEY and LLM_MODEL are explicitly configured. Follow organizational evidence/data-handling requirements before enabling that configuration. Live provider calls were not required for the local demonstration. Document instructions never trigger shell execution or tools.

Provision real users from the backend directory with `python -m flask --app run create-user --email auditor@example.com --username "Auditor Name" --role auditor` (or reviewer/administrator). The CLI prompts for the password without echoing it. This is an operator action, not a public registration privilege path.
